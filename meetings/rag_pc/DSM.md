# meet.sevskiy.com через DSM (етап 0, робить людина)

Мета — відкривати стенд за адресою **https://meet.sevskiy.com** з нормальним сертифікатом (без попередження
браузера) і перевірити, чи ця адреса працює з офісних ПК.

Маршрут: браузер → DSM 192.168.2.142 (сертифікат Let's Encrypt) → `https://192.168.2.68:8791` (стенд).
Наявний маршрут app.sevskiy.com → розподільник `D:\RAG-router` не чіпаємо: він не пропускає WebSocket.

> ⚠️ Поки в стенді немає входу (вхід з'явиться на етапі 1 — одноразові ключі з Minerva), адреса має
> відкриватися **лише з офісної мережі**. Для цього в кроці 2 — профіль доступу «лише LAN».

## 1. DNS

У провайдера домену sevskiy.com додати запис **CNAME `meet` → те саме ім'я, на яке вказує `app`**
(або запис A з тією самою IP-адресою, що й у app.sevskiy.com).

## 2. Зворотний проксі в DSM

DSM → Панель керування → Портал входу → Додатково → **Зворотний проксі** → Створити:

| Поле | Значення |
|---|---|
| Назва | Minerva Meeting Bench |
| Джерело | HTTPS · `meet.sevskiy.com` · порт 443 |
| Призначення | **HTTPS** · `192.168.2.68` · порт **8791** |
| Власний заголовок | Створити → **WebSocket** (додає Upgrade і Connection) |
| Додаткові налаштування | тайм-аути з'єднання 60 с, надсилання **3600 с**, читання **3600 с** |
| Профіль доступу | новий «Лише LAN»: дозволити `192.168.2.0/24`, решту заборонити |

## 3. Сертифікат

DSM → Безпека → Сертифікат → Додати → Let's Encrypt для `meet.sevskiy.com` (або дописати його до сертифіката
app.sevskiy.com як альтернативне ім'я) → «Налаштування» → вибрати цей сертифікат для запису
`meet.sevskiy.com` зворотного проксі.

## 4. Перевірка з офісного ПК

1. Відкрити https://meet.sevskiy.com. Має з'явитися стенд без попередження про сертифікат.
2. Якщо адреса не відкривається, а https://192.168.2.68:8791 відкривається, роутер не повертає запити
   офісних ПК на власну зовнішню адресу (NAT loopback). Тоді потрібен локальний DNS-запис
   `meet.sevskiy.com → 192.168.2.142` (у роутері або DNS Server на DSM).
3. Якщо великі файли через meet.sevskiy.com обриваються з помилкою 413, це обмеження проксі DSM.
   Файли тоді завантажуйте напряму через https://192.168.2.68:8791.

## 5. Що змінити на RAG-ПК після цього

- `D:\Meeting\data\config.json`: `"trusted_proxies": ["192.168.2.142"]`. Тоді стенд бачить адресу людини
  із заголовків DSM. Перезапуск: `stop.ps1`, потім `start.ps1`.
- Брандмауер — дописати DSM до правила порту 8791 (PowerShell від адміністратора):

  ```powershell
  Set-NetFirewallRule -DisplayName 'Minerva Meeting Bench' -RemoteAddress 192.168.2.108,192.168.2.120,192.168.2.142
  ```
