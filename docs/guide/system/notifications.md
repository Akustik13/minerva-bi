## Що це

[Налаштування сповіщень](/admin/config/notificationsettings/) — одна сторінка для всіх системних повідомлень:

- **канали** — пошта (SMTP) і Telegram;
- **події** — нове замовлення, зміна статусу замовлення чи посилки, підсумок синхронізацій;
- **листи клієнтам** — про відправку й підтвердження замовлення;
- **звіти** за розкладом і планові попередження (критичний склад, прострочені строки).

Той самий SMTP Minerva використовує для запрошень співробітникам і листів «Забули пароль?».

Окремо налаштовуються: нагадування календаря — [📅 Календар → Сповіщення](/calendar/settings/)
([Календар](guide:calendar/overview)), сповіщення цін DigiKey — [Ціни DigiKey](guide:digikey/prices), листи
магазину — [Пошта магазину](guide:shop/mail), звіти робочого часу — [Звіти](guide:worktime/reports).

## Крок 1. Пошта (SMTP)

1. Відкрийте [Налаштування сповіщень](/admin/config/notificationsettings/), блок **«📧 Email (SMTP)»**.
2. Заповніть:
   - **«SMTP Host»**, **«SMTP Port»** і **«TLS (STARTTLS)»** або **«SSL»** (лише одне);
   - **«SMTP Login (email)»**, **«SMTP Password»**;
   - **«Від кого (From)»** — порожньо = логін;
   - **«Отримувачі (To)»** — адреси команди через кому: `info@example.com, chef@example.com`;
   - **«Шаблон підпису»** — `{name}` замінюється іменем співробітника.
3. Увімкніть **«Надсилати email-сповіщення»** → **«Зберегти»**.
4. Унизу в блоці **«🚀 Дії»** натисніть **«📧 Надіслати тест»** → «✅ Тестовий email надіслано!».

| Поштовик | SMTP Host | Порт | Шифрування |
|---|---|---|---|
| IONOS | `smtp.ionos.de` | 587 | TLS |
| Gmail | `smtp.gmail.com` | 587 | TLS, пароль застосунку (Google → Безпека → Паролі застосунків) |
| будь-який з SSL | — | 465 | SSL |

## Крок 2. Telegram

1. У Telegram відкрийте **@BotFather** → `/newbot` → назва (наприклад «Minerva Alerts») → ім'я бота, що
   закінчується на `bot`. Скопіюйте токен вигляду `123456:ABC-…`.
2. Chat ID:
   - особистий чат — напишіть своєму боту `/start`, потім свій ID покаже **@userinfobot**;
   - група — додайте бота в групу, ID починається з `-100…`;
   - канал — зробіть бота адміністратором з правом публікації, Chat ID — `@назва_каналу`.
3. Розгорніть блок **«📱 Telegram»** (клік на заголовок): **«Bot Token»**, **«Chat ID»**, увімкніть
   **«Надсилати Telegram-сповіщення»** → **«Зберегти»**.
4. **«📱 Тест Telegram»** у блоці **«🚀 Дії»** → у чаті з'явиться тестове повідомлення.

## Крок 3. Про що повідомляти

Кожна подія має окремі галочки «Email: …» і «Telegram: …».

| Блок | Коли надходить | Що налаштовується |
|---|---|---|
| **«📬 Нові замовлення»** | одразу, як з'явилось замовлення з будь-якого джерела | **«Email: нове замовлення»**, **«Telegram: нове замовлення»**; **«Приклад повідомлення»** — як виглядатиме |
| **«🤖 DigiKey авто-підтвердження»** | DigiKey-замовлення підтверджено автоматично | окремо від «Нових замовлень» — увімкніть одне з двох, щоб не дублювалось |
| **«⚙️ Вміст сповіщень»** | для двох блоків вище | **«💰 Сума замовлення»**, **«📊 Кількість замовлень клієнта (CRM)»**, **«📦 Дедлайн відправки»**, **«🏪 Стан складу»**, **«📄 Посилання на Datasheet»**, **«🖼️ Фото товарів у Telegram»** |
| **«⚙️ Оновлення системи (синхронізації)»** | DigiKey чи авто-трекінг знайшли зміни | **«Не надсилати якщо змін не виявлено»** |
| **«🔄 Зміна статусу замовлення»** | статус змінено | які зміни: **«→ В обробці»**, **«→ Відправлено»**, **«→ Доставлено»**, **«→ Скасовано»** |
| **«📦 Статус відправлення (посилки)»** | статус посилки змінено вручну чи автотрекінгом | **«→ Передано перевізнику»**, **«→ Етикетка готова»**, **«→ В дорозі»**, **«→ Доставлено»**, **«→ Помилка»**, **«→ Скасовано (посилка)»** |

## Листи клієнтам

**«📧 Повідомлення клієнту про відправку»** — кнопка **«📧 Надіслати клієнту»** у картці замовлення:

- **«Кнопка «Надіслати клієнту»»** — показувати кнопку; **«Авто-відправка (без підтвердження)»** — надсилати
  самостійно;
- **«Тема листа клієнту (шаблон)»**, **«CC (копія) за замовчуванням»**, текст для країн ЄС і окремий текст для
  решти світу (з попередженням про мито) — Minerva вибирає за країною замовлення;
- змінні: `{order_number}` `{customer_name}` `{tracking_number}` `{carrier}` `{shipped_date}` `{items}` `{ship_address}`.

**«📥 Підтвердження отримання замовлення»** — кнопка **«📥 Підтвердження замовлення»** у картці замовлення
або автоматично при створенні (**«Авто-відправка при створенні замовлення»**). **«Джерела (фільтр)»** —
лише для вказаних джерел, наприклад `digikey, webshop`; порожньо — для всіх. Змінні: `{order_number}`
`{customer_name}` `{order_date}` `{items}`.

## Звіти за розкладом

| Звіт | Блок | Що в ньому |
|---|---|---|
| **Щоденний** | **«📅 Щоденний звіт»** | очікують відправки, прострочені, нові замовлення, доставлені, критичний залишок — кожен розділ окремою галочкою |
| **Тижневий** | **«📅 Щотижневий звіт»** | ще кількість відправлень і топ-5 товарів за тиждень |
| **Місячний** | **«📅 Місячний звіт»** | ще виручка місяця з порівнянням і топ-10 товарів |

Щоденний: **«Увімкнути звіт»**, канали **«Email звіт»** / **«Telegram звіт»**, **«Частота»** (Щодня /
Щотижня), **«Час надсилання»** (за часом Берліна), **«Не надсилати у вихідні»**, **«Не надсилати у свята»** і
**«Країна свят»**. Кнопки перевірки: **«📊 Надіслати звіт зараз»**, **«📊 Надіслати тижневий звіт зараз»**,
**«📊 Надіслати місячний звіт зараз»**.

Тижневий — **«День тижня»** і **«Час відправки»**, місячний — **«День місяця (1–28)»** і **«Час відправки»**
у своїх блоках; канали — ті самі **«Email звіт»** / **«Telegram звіт»**, що в щоденному.

Розклад сервера Minerva щохвилини перевіряє всі три звіти й надсилає кожен у його день і час (або перший раз
після цього часу того ж дня) — не більше одного разу на день; коли він пішов, видно в полях **«… останній»**.
Не вдалося надіслати (помилка SMTP чи Telegram) — наступна спроба не раніше ніж за 30 хвилин і не більше трьох
спроб за день. Кнопки «… зараз» надсилають одразу, без огляду на розклад.

## Критичний склад і прострочені строки

**«🔔 Планові сповіщення (cron)»**: **«Critical stock alerts»** — товари, яких вистачить менш ніж на 1,5 місяця
продажів; **«Overdue deadline alerts»** — замовлення з минулим строком відправки (**«Оповіщати через N днів
після дедлайну»**). **«⏱️ Розклад»** — **«Мінімальний інтервал між надсиланнями (год)»**.

**«🔔 Перевірити та надіслати зараз»** перевіряє й надсилає одразу, без огляду на інтервал.

Розклад сервера перевіряє ці попередження сам кожні 15 хвилин і надсилає їх, лише коли є критичні товари чи
прострочені замовлення, — не частіше, ніж **«Мінімальний інтервал між надсиланнями (год)»** (0 — раз на годину).
Не хочете автоматичних попереджень — зніміть обидві галочки. Помилка надсилання — повтор не раніше ніж за
30 хвилин, не більше трьох разів на день.

## Ранковий брифінг

[Налаштування брифінгу](/admin/config/briefingsettings/) — щоранку AI складає кожному співробітнику короткий
огляд і надсилає в Telegram.

1. **«Увімкнено»** — брифінг надсилається кожному, у кого в профілі є **«Telegram ID»**
   ([Мої налаштування](guide:system/my-settings)).
2. **«📋 Що включати у брифінг»**: **«📦 Замовлення місяця»**, **«💰 Виручка місяця»**, **«⏰ Прострочені
   дедлайни»**, **«🔔 Нагадування на сьогодні»**, **«🔥 Критичний залишок»**, **«📬 Нові листи від клієнтів»**,
   **«📁 Проєкти: потребує уваги»** (кожному — його проєкти, де клієнт чекає відповіді, Angebot без рішення,
   минув строк).
3. **«Додаткові інструкції для AI»** — за бажанням: мова, тон, на чому наголошувати.
4. **«📤 Тестова відправка в Telegram»** — надіслати брифінг усім зараз.

Брифінг надсилає Telegram-бот Minerva AI: його токен — **«Telegram Bot Token»** у
[Налаштуваннях AI](/admin/strategy/aisettings/). Кожен співробітник має один раз натиснути **Start** у чаті з
цим ботом, інакше Telegram не дозволить йому писати.

Брифінг надходить щодня в **«Час відправки»** (за часом Берліна) з блоку **«⏰ Розклад»** — розклад сервера
перевіряє цей час щохвилини й надсилає брифінг один раз на день; коли він пішов, видно в полі **«Останній брифінг
за розкладом»**. Якщо сервер у цей час не працював, брифінг ще піде протягом трьох годин, пізніше — уже
наступного дня. **«📤 Тестова відправка в Telegram»** надсилає одразу й розкладу не змінює.

## Часті питання та проблеми

| Повідомлення / симптом | Що зробити |
|---|---|
| «⚠️ Telegram вимкнено або не налаштований (Bot Token / Chat ID).» | заповніть **«Bot Token»**, **«Chat ID»** і увімкніть **«Надсилати Telegram-сповіщення»** |
| `Forbidden: bot was blocked by the user` | ви заблокували бота — знайдіть його в Telegram і розблокуйте |
| `Chat not found` | неправильний Chat ID або бота немає в групі — напишіть боту `/start` чи додайте його в групу |
| `Unauthorized` | неправильний токен — скопіюйте його з @BotFather ще раз |
| `have no rights to send a message` | бот не адміністратор каналу |
| помилка SSL / `WRONG_VERSION_NUMBER` | порт не відповідає шифруванню: 587 — TLS, 465 — SSL |
| Gmail: `Username and Password not accepted` | потрібен пароль застосунку, а не звичайний пароль |
| тест пройшов, а попереджень немає | немає критичних товарів чи прострочених замовлень або не минув інтервал — **«🔔 Перевірити та надіслати зараз»** |

Стан пошти й Telegram одним поглядом — [⚙️ Система → Інтеграції](/admin/config/integrations/).
