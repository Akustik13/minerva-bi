## Що це

Резервна копія — файл, з якого можна повернути Minerva до стану на момент копіювання: після помилкового
імпорту, видалення чи збою NAS. Сторінка [💾 Резервне копіювання](/admin/backup/backupplaceholder/) — для
адміністратора.

| Вид | Що в ньому | Файл |
|---|---|---|
| **🗄️ База даних** | усі дані: замовлення, клієнти, товари, листи, налаштування, користувачі | `.sql` |
| **📁 Медіа файли** | файли: документи замовлень, фото й даташити товарів, вкладення, етикетки | `.zip` |
| **📦 Повний бекап** | база даних + медіа файли | `.sql` + `.zip` |
| **⚙️ Налаштування** | користувачі, групи, ключі API, налаштування DigiKey, сповіщень, системи, реквізити компанії, доставки й перевізників, бекапу | `.mbackup` |

> ⚠️ Файл `.mbackup` і копія бази містять ключі API й паролі поштових скриньок — зберігайте їх як секрет.

На сторінці [⚙️ Система](/dashboard/system/) рядок **«💾 Backup:»** показує, коли була остання вдала копія:
зелений — сьогодні або вчора, жовтий — до тижня, червоний — давно або ніколи.

## Зробити копію зараз

1. Відкрийте [Резервне копіювання](/admin/backup/backupplaceholder/), блок **«🔄 Швидкий бекап»**.
2. У потрібній картці натисніть **«Зробити бекап»**. Замість «Готово до запуску» з'явиться хід і результат:
   файл, розмір, час.
3. Копія з'явиться в **«📋 Історія бекапів (останні 50)»**: **«⬇️ ПК»** — завантажити файл на свій комп'ютер,
   **🗑** — видалити запис і файл.

**«💾 Також зберегти на ПК:»** → **«📂 Вибрати папку»** — у Chrome чи Edge виберіть папку на своєму ПК, і
кожна наступна копія збережеться ще й туди (у Firefox так не можна).

> 💡 Тримайте свіжу копію не лише на NAS: якщо зламається сам NAS, копія на ньому не допоможе.

## Автобекап

Блок **«⚙️ Налаштування автобекапу»**:

1. **«📂 Шлях для збереження бекапів»** — папка на сервері (📂 — вибрати зі списку). Порожньо — тека
   `backups` у теці Minerva.
2. **«Включати медіа у повний бекап»** — з файлами чи лише база.
3. **«Автобекап увімкнено»**, **«🕐 Розклад»** — Щодня або Щотижня.
4. **«🗑️ Зберігати останніх N бекапів»** — старіші видаляються самі (наприклад 10).
5. **«💾 Зберегти налаштування»**.

Автобекап Minerva запускає сама, нічого на сервері налаштовувати не треба: перша копія — приблизно через
годину після ввімкнення, далі за розкладом. З увімкненим **«Включати медіа у повний бекап»** робиться повний
бекап, інакше — лише база даних. Копію **«⚙️ Налаштування»** автобекап не робить — натискайте її вручну після
важливих змін (нові користувачі, ключі).

## Відновлення

> ⚠️ **Незворотно.** Відновлення бази повністю замінює поточні дані — усе, що змінилося після дати копії,
> зникне. Відновлення медіа перезаписує поточні файли. Перед відновленням зробіть свіжу копію поточного стану.

**З копії зі списку** (блок **«🔄 Відновлення з бекапу»**, таблиця знайдених файлів):

1. У рядку потрібної копії — **«🔄 Відновити»**.
2. У вікні **«Підтвердіть відновлення»** перевірте тип, файл і дату → **«✅ Так, відновити»**.
3. Дочекайтесь результату у вікні й оновіть сторінку.

**З файлу на ПК** — **«📤 Завантажити файл бекапу з ПК…»**: **«📎 Файл бекапу (.sql / .zip / .mbackup)»**,
**«Тип»** (База даних / Медіа файли / Повний / Налаштування) → **«📤 Відновити з файлу»**.

**За шляхом на сервері** — **«📂 Вказати шлях вручну…»**: **«🗄️ Шлях до файлу БД (.sql)»**, **«Тип відновлення»**,
для повного — ще **«📁 Шлях до архіву медіа (.zip) — для повного відновлення»** → **«🔄 Відновити з вказаного
шляху»**.

**Налаштування (.mbackup)** — вікно **«Відновлення налаштувань»** → **«✅ Відновити налаштування»**: користувачі,
ключі API, конфігурація ботів і системи перезаписуються з файлу, решта даних не змінюється.

## Оновлення системи й консоль

Угорі сторінки — інструменти адміністратора сервера:

- **«🔄 Оновлення системи»** — **«🔍 Перевірити оновлення»** (покаже нові зміни), **«🚀 Повне оновлення»**
  (код → статика → міграції → перезапуск) і окремі кроки: **«⬇️ Оновити код (git pull)»**, **«📦 Зібрати
  статику»**, **«🗄️ Застосувати міграції»**, **«🧩 Оновити модулі»**, **«🔁 Перезапустити воркери»**;
- **«💻 Консоль команд»** — виконати службову команду Minerva (**«▶ Виконати»**); лише для користувача зі
  статусом суперкористувача.

> ⚠️ Перед оновленням зробіть **«📦 Повний бекап»**.

## Часті питання та проблеми

**«БД недоступна (таймаут 5с)…»** — для копії налаштувань потрібна робоча база даних; перевірте, чи запущено
Minerva повністю, і повторіть.

**«Тільки .sql або .zip файли» / «Очікується файл .mbackup»** — вибрано файл не того виду; перевірте **«Тип»**.

**«Недозволений шлях або тип файлу»** — у шляху є `..` або неправильне розширення.

**«Бекапів не знайдено в директорії бекапів.»** — копій ще не було або змінено **«📂 Шлях для збереження
бекапів»**; старі файли лежать у попередній папці.

**Чи можна вимкнути контейнери NAS?** Зупиняти Minerva можна, але ніколи не видаляйте томи Docker
(`docker-compose down -v`): так зникає сама база даних.
