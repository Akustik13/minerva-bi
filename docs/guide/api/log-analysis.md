## Що це

[📜 Журнал API](/admin/api/apirequestlog/) записує кожен запит ключа. Тепер кожен рядок має пояснення одним
реченням (**«Що сталося»**), а сторінка **«📊 Аналіз журналу»** збирає все за період: скільки запитів, що
читали й що змінювали, де отримали відмову, **які саме товари й замовлення** програма отримала.

## Що сталося — рядок журналу людською мовою

Колонка **«Що сталося»** у журналі й поле в картці запиту:

| Запит | Що сталося |
|---|---|
| `GET /api/v1/products/?with_stock=1&page_size=500` | API RAG прочитав список товарів зі складом — 169 записів (сторінка 1, page_size 500) |
| `POST /api/v1/orders/` | webshop створив замовлення PO-31728-001 (статус received; поля: client, currency, lines, order_number) |
| той самий запит ще раз | webshop повторно надіслав замовлення … — воно вже було, нового не створено |
| `POST /api/v1/stock-movements/` | crm записав рух складу (прихід 12 × FT220407, доступно після: 37) |
| `GET /api/v1/stock/FT220407/` понад ліміт | partner отримав відмову 429 (читання залишку товару FT220407): денний ліміт різних записів |

У **картці запиту** (клік на час у журналі):

- **«Усі записи відповіді»** — кожен товар / замовлення, який ключ отримав (до 2000 у запиті), з посиланнями на
  картки в Minerva. Раніше журнал зберігав лише перші 10;
- **«Що змінилось»** — для POST / PATCH / PUT / DELETE: **назви полів**, які надіслала програма (без значень —
  тіло запиту не зберігається), і що відповіла Minerva: номер замовлення, статус, рух складу, відкинуті поля.

## Як відкрити аналіз

- [📜 Журнал API](/admin/api/apirequestlog/) → кнопка **«📊 Аналіз журналу»** вгорі праворуч (з фільтром ключа
  — одразу для цього ключа);
- картка ключа → **«📊 Аналіз журналу ключа»** (блоки «🔍 Що бачить…» і «Активність»);
- [одразу сторінка](/admin/api/apirequestlog/analysis/).

## Фільтри

- **«Ключ»** — усі, один ключ або **«Невідомі ключі (401)»** (спроби з неправильним ключем);
- **«Період»** — **«сьогодні»**, **«7 днів»**, **«30 днів»** або **«Від»** / **«До»**;
- **«Відповідь»** — успішні, помилки, 401 / 403 / 429 / 5xx; **«Що робив»** — читання чи зміни;
- **«Показати»**. Записи журналу зберігаються 60 днів.

## Що на сторінці

- **Плитки**: запитів, 👁 читання, ✏️ зміни, ⚠ помилки (з них відмов 401 / 403 / 429), 📦 записів віддано (сума
  записів у всіх читаннях), 🔢 різних записів, 🌐 IP-адрес, ⏱ середній час.
- **📈 Запити по днях** — стовпчики читання / зміни / помилки й лінія «Записів віддано».
- **📦 Які записи отримано** — кожен товар / замовлення / клієнт, який ключ отримав, і в скількох запитах, з
  пошуком і посиланням на картку в Minerva. Так видно, наприклад, що партнер забирав лише 20 потрібних
  артикулів чи весь каталог.
- **✏️ Що змінювалось** — кожна зміна за період рядком «Що сталося» (клік на час — картка запиту).
- **⚠ Відмови й помилки** — код, чому (людською мовою), скільки разів, коли востаннє.
- **🔌 Що найчастіше робив** — дії з кількістю запитів, помилок, записів і часом.
- **🌐 IP-адреси** і **🧩 Програми (User-Agent)** — звідки й чим ходили.
- **🐢 Найдовші запити** і **📦 Найбільші відповіді**.

## ⬇ CSV

Кнопка **«⬇ CSV»** вивантажує журнал з тими самими фільтрами: коли, ключ, IP, метод, адреса, параметри, дія,
право, відповідь, код помилки, записів, **усі записи відповіді**, що змінилось, примітка, мс, програма і
«Що сталося». Файл відкривається в Excel (роздільник «;»).

> 💡 Щоб перевірити, що ключ **може** робити (а не що робив), — [Що бачить і що може змінити ключ](guide:api/key-insight).

## Часті питання та проблеми

**Записів віддано багато, а різних записів мало** — програма часто перечитує той самий каталог (напр. RAG
синхронізує товари). Зменшіть частоту або обмежте ключ ([Ключі API](guide:api/keys)).

**«Які записи отримано» порожнє для старих днів** — повний список записів журнал зберігає з 30.10.2026; старіші
рядки мають лише перші 10 номерів, вони теж враховані.

**Аналіз не показує запитів ключа** — у ключа вибрано **«Журнал запитів»** = «Лише помилки» чи «Не
записувати», або період не той.
