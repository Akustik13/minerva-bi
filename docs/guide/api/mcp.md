## Що це

**MCP** (Model Context Protocol) — спосіб, яким агенти на кшталт **Claude Code** чи **Claude Desktop** працюють з
чужими програмами. Minerva дає їм ті самі інструменти, що й [🧩 Завданням агенту](guide:inventory/agent-tasks):

- **читати** — знайти товари, картку товару, даташит, локації складу, магазини й DigiKey, замовлення до відправки;
- **пропонувати** — зміну в картці чи параметрах, прихід на склад, новий товар, подію в календарі, показ / ціну в
  магазині, ціни чи строк на DigiKey, чернетку відправлення, трек-номер чи статус замовлення.

Сам агент **нічого не змінює**: кожна пропозиція потрапляє в «🧩 Завдання агенту» людини ключа й чекає її ✓ — так
само, як пропозиції агента Minerva.

> ℹ️ Пошти й пошуку в інтернеті через MCP немає: листи бачить лише власник скриньки, а лист надсилає лише людина.

## Як підключити

### 1. Ключ API

У [🔑 API ключах](/admin/api/apikey/add/) створіть окремий ключ, напр. «Claude Code — Anna»:

| Поле | Що вписати |
|---|---|
| Права | `agent:read` — лише читання; `agent:write` — ще й пропозиції |
| **🤖 Агент (MCP) — від імені кого** | людина, яка перевірятиме пропозиції (у неї має бути розділ «🤖 Агент») |
| Магазин | порожньо — ключ сайту магазину для MCP не підходить |

Обмеження (IP, ліміти) і [журнал запитів](guide:api/keys) діють, як для будь-якого ключа.

### 2. Claude Code

У терміналі (адресу й ключ підставте свої):

```bash
claude mcp add --transport http minerva {{base_url}}/api/v1/mcp/ --header "Authorization: Bearer <ключ>"
```

Перевірка — команда `/mcp` у Claude Code: «minerva · connected» і список інструментів.

### 3. Claude Desktop

Claude Desktop підключається через `mcp-remote` (потрібен Node.js). **Settings → Developer → Edit Config**, у файл
`claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "minerva": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "{{base_url}}/api/v1/mcp/", "--header", "Authorization:${MINERVA_AUTH}"],
      "env": {"MINERVA_AUTH": "Bearer <ключ>"}
    }
  }
}
```

Перезапустіть Claude Desktop — у чаті з'явиться значок інструментів «minerva».

> ⚠️ Ключ — як пароль: не публікуйте файл налаштувань і не пересилайте ключ у чатах.

## Як працювати

Пишіть агенту своїми словами, напр. в Claude Code:

- «Знайди в Minerva антени AN2202…, прочитай даташити й запропонуй вагу однієї штуки та країну виробника».
- «Які товари категорії Filter не показані в магазині sevskiy? Запропонуй показати ті, що є на складі».
- «Перевір ціни на DigiKey для FT220407 — чи вони за правилами Minerva?»

Перша пропозиція створює завдання «MCP · <назва клієнта> · <дата>» у **🧩 Завданнях агенту** людини ключа (одне на
сесію Claude; усі пропозиції сесії — разом). Агент отримує посилання на сторінку перевірки й може його показати вам.
Далі — як завжди: [перевірити й застосувати](guide:inventory/agent-tasks) ✓ / ✕.

| Інструмент | Що робить | Право ключа |
|---|---|---|
| `find_products`, `get_product` | пошук і картка товару | `agent:read` |
| `read_datasheet` | текст даташита (файл, посилання або правило посилань складу) | `agent:read` |
| `list_locations`, `list_shops`, `get_sales_channels` | локації, магазини, позиції в магазинах і на DigiKey | `agent:read` |
| `propose_change`, `propose_attribute` | зміна поля картки / технічного параметра | `agent:write` |
| `propose_stock_in`, `propose_product` | прихід на склад, новий товар | `agent:write` |
| `propose_event` | подія в календарі людини ключа | `agent:write` |
| `propose_shop`, `propose_dk_prices`, `propose_dk_lead` | показ / ціна в магазині, ціни DigiKey за правилами, строк DigiKey | `agent:write` |
| `orders_to_ship`, `get_order`, `list_carriers` | що треба відправити, замовлення з адресою, складом і упаковкою, перевізники (людина ключа — з правом на Продажі) | `agent:read` |
| `propose_shipment`, `propose_order_update` | чернетка відправлення (оформлює людина), трек-номер / кур’єр / статус / строк замовлення | `agent:write` |

## Часті питання та проблеми

**401 Unauthorized.** Ключа немає в заголовку або він неправильний: `Authorization: Bearer <ключ>` (працює й
`Token <ключ>`).

**403 «У ключа не вказано «🤖 Агент (MCP) — від імені кого»».** Заповніть це поле в картці ключа.

**403 на пропозиції, а читання працює.** У ключа лише `agent:read` — додайте `agent:write`.

**403 «Людина ключа не має права на завдання агенту».** Її ролі бракує розділу «🤖 Агент» — див.
[👁 Як бачить Minerva](/admin/core/userprofile/).

**Агент каже «запропоновано», а в картці товару нічого не змінилось.** Так і має бути — відкрийте
[🧩 Завдання агенту](/admin/agent/agenttask/) і застосуйте ✓.

**Хто що робив?** Кожен виклик — у «Кроках агента» на сторінці завдання і в журналі запитів ключа.
