## Що це

Сторінка відповідає на три питання про **один ключ API**:

1. **Що він може** — кожна адреса API: дозволена чи ні, які поля ключ отримує, які поля може надіслати й що
   зміниться в Minerva.
2. **Що він бачить зараз** — **«👁 Приклад даних»**: перші записи саме так, як їх отримала б програма з цим
   ключем.
3. **Що змінить запит** — **«🧪 Що змінить запит»**: вставте тіло запиту (JSON), і Minerva скаже, що сталося б,
   нічого не записуючи.

Таблиця складається з коду Minerva, тож нова адреса API з'являється тут сама.

## Де знайти

1. [🔑 API Токени](/admin/api/apikey/) → відкрийте ключ.
2. Блок **«🔍 Що бачить і що може змінити цей ключ»**: коротко — скільки адрес ключ читає, скільки змінює
   (і які саме), скільки заборонено правами.
3. Кнопка **«🔍 Таблиця можливостей, приклад даних і симуляція»** відкриває сторінку. Поруч —
   **«📊 Аналіз журналу ключа»** ([Аналіз журналу API](guide:api/log-analysis)).

## Як читати сторінку

**Плитки вгорі**: **«Читає адрес»**, **«Змінює адрес»** (POST / PATCH / PUT / DELETE), **«Заборонено правами»**.

**«🛡 Права й обмеження ключа»** — усе, що звужує ключ, людською мовою: чи працює ключ (вимкнений або
прострочений — будь-який запит отримає 401), права, магазин, джерело замовлень, дозволені IP-адреси, ліміти
запитів (і скільки вже використано), «Різних записів за добу», «Лише ці поля», режим журналу, вебхуки ключа.

**Таблиця** — розділи 📦 Склад, 🏷 Товари, 🧾 Замовлення, 🚚 Доставка, 👥 Клієнти CRM, 📥 Закупівлі,
🏪 Магазин і сайт, 👤 Кабінет покупця, 💳 Оплати, 🔔 Вебхуки, 🧠 База знань, 🔌 Службові. Колонки:

| Колонка | Що в ній |
|---|---|
| **Запит** | метод і адреса, під нею — потрібне право (`🔑 stock:read`) |
| **Що робить** | коротко; для змін — ✏️ що саме зміниться в Minerva (рух складу, нове замовлення, повернення товару…) |
| **Цьому ключу** | ✅ дозволено / ⛔ немає права / 🚫 не підтримується (405) / 🔓 без ключа; примітки — як ключ звужено (лише замовлення свого магазину, лише поля оплати…) |
| **Дані** | для читання — **«Повертає поля»** (з урахуванням «Лише ці поля» і ключа сайту), для змін — **«Приймає поля»**, які ключ може надіслати |

Фільтри над таблицею: **«Усі адреси»**, **«✅ Дозволені»**, **«✏️ Що може змінити»**, **«⛔ Заборонені»** і пошук
за адресою, полем чи описом (напр. `payment` — усі адреси, де є поля оплати).

> 💡 Ключ сайту магазину (поле «Магазин» або «Джерело замовлень» = код магазину) у таблиці видно одразу:
> замовлення — лише свого магазину, `PATCH /orders/{pk}/` приймає лише `payment_status`, `payment_reference`,
> `payment_method`, `/products/` — без закупівельної ціни й приміток.

## 👁 Приклад даних

Що програма з цим ключем отримала б **зараз**:

1. Внизу сторінки, блок **«👁 Приклад даних — що ключ отримав би зараз»** (або **«👁 приклад»** у рядку
   таблиці).
2. **«Адреса»** — виберіть, напр. `GET /api/v1/products/`. Для адреси з `{sku}` чи `{pk}` з'явиться поле
   **«Значення»** — артикул або номер.
3. **«Параметри адреси»** — як у програми, напр. `with_stock=1` або `search=FT220`.
4. **«Записів»** — скільки показати (до 20).
5. **«👁 Показати»** — відповідь, кількість записів («показано 5 з 169»), поля запису й сам JSON.

Перегляд іде тим самим шляхом, що й справжній запит: права, магазин, «Лише ці поля», «Різних записів за добу».
Але він **не рахується** в ліміти й «різних записів за добу», **не змінює** «Останнє використання» ключа і
**не пишеться** в [📜 Журнал API](/admin/api/apirequestlog/) — журнал показує лише дії самих програм. Хто й
коли дивився дані як ключ — записано в журналі аудиту Minerva.

> ℹ️ «Дозволені IP-адреси» в перегляді не перевіряються — запит іде з Minerva, а не з адреси програми.
> Секрети у відповіді (секрет вебхука тощо) замасковано.

Перегляд відкриває лише читання без побічних дій: склад, рухи, локації, категорії, товари, каталог магазину,
замовлення, відправлення, клієнти, закупівлі, вебхуки, доставка магазину. Не відкриває — пошук на сайті (пише
журнал пошуку, може викликати платний AI), налаштування пошти й помічника сайту (містять паролі), кабінет
покупця, базу знань, файли.

## 🧪 Що змінить запит

Перевірка запиту на зміну **без запису** — напр. перед тим, як дати партнеру право `orders:write`, або щоб
зрозуміти, чому програма отримує 400:

1. Блок **«🧪 Що змінить запит — перевірка без запису»** (або **«🧪 перевірити»** у рядку таблиці).
2. **«Запит»** — напр. `POST /api/v1/orders/`; для `{pk}` — номер у полі **«Значення»**.
3. **«Тіло запиту (JSON)»** — підставляється приклад; вставте те, що надсилає програма.
4. **«🧪 Перевірити»**.

Відповідь:

- **«201 · Запит пройде: Minerva створить замовлення.»** і **«Що сталося б»**: номер і джерело замовлення,
  позиції з цінами, що буде зі складом («товар спишеться одразу», «зарезервується до відправки»);
- для інвентаризації — `«FT220407» на «MAIN»: 10 → 25 (коригування +15)`; для руху складу — залишок до й після;
- для зміни замовлення чи товару — `поле: «було» → «стане»`; для ключа сайту — які поля Minerva відкине;
- для скасування — статус і що повернеться на склад;
- **відмова** з кодом, як у справжній відповіді: 400 (помилки по полях), 404 (товару / замовлення немає або ключ
  його не бачить), 409 (недостатньо товару, замовлення вже відправлене), 403 (немає права).

Тіло перевіряється тим самим перевірником, що й справжній запит, і Minerva лише **читає** базу (товар за
артикулом, залишок, наявне замовлення) — у транзакції, яка завжди відкочується.

> ⚠️ Не перевіряються (з поясненням замість запуску): закупівлі з CRM (сервіс перевіряє тіло лише під час
> запису), кабінет покупця (листи, сесії, паролі), оплати Stripe, база знань, тестова подія вебхука (справжній
> запит назовні), вхід персоналу й журнал сайту. Ціни магазину зі ступенями, мінімальні кількості й доставка
> для `shop: true` перевіряються лише справжнім запитом.

## Хто може

- **Таблицю й обмеження** бачить кожен, хто може переглядати ключі API.
- **«👁 Приклад даних»** і **«🧪 Що змінить запит»** — лише ті, хто може **змінювати** ключі API (вони діють від
  імені ключа). Секрет ключа на сторінці не показується.

## Часті питання та проблеми

**У прикладі менше записів, ніж очікувалось** — діє **«Різних записів за добу»**: під JSON написано, скільки
приховано й скільки ключ уже бачив сьогодні.

**Записи в прикладі порожні `{}`** — **«Лише ці поля у відповідях»** не містять жодного поля цієї адреси (у
таблиці: «жодне з «Лише ці поля» тут не повертається»).

**Приклад відповідає 401** — ключ вимкнений або прострочений. **403** — у ключа немає права на цю адресу.

**Симуляція каже «пройде», а програма отримує відмову** — перевірте «Дозволені IP-адреси» й ліміти ключа
([Ключі API](guide:api/keys)) і подивіться відмову в [Аналізі журналу](guide:api/log-analysis).
