## Що це

**Ключ API** — пароль для програми. Кожна система (сайт магазину, CRM, RAG, скрипт партнера) отримує свій ключ;
ключ визначає, **що** програма може робити (права), **звідки й скільки** (обмеження), і кожен його запит
записується в [📜 Журнал API](/admin/api/apirequestlog/).

## Як створити ключ

1. [🔑 API Токени](/admin/api/apikey/) → **«Додати API Ключ»** (або [одразу форма](/admin/api/apikey/add/)).
2. Блок **«Загальне»**:
   - **«Назва»** — хто користується: `webshop`, `crm`, `partner-muster`;
   - **«Активний»** — зніміть, щоб миттєво вимкнути ключ;
   - **«Дійсний до»** — для тимчасових ключів (після дати — 401);
   - **«Магазин»** — для ключа сайту: асортимент і ціни якого магазину він бачить і куди йдуть його замовлення
     ([Магазин](guide:shop/overview));
   - **«Джерело замовлень»** — код джерела, яке отримають замовлення цього ключа, якщо програма його не передала
     (напр. `webshop`; для CRM закупівель — `crm`).
3. **«Права доступу (scopes)»** — позначте лише потрібне (таблиця нижче).
4. За потреби — **«🛡 Обмеження»** і **«📜 Журнал запитів»** (нижче).
5. **«Зберегти»**. Розгорніть **«Технічна інформація»** → **«API Ключ (скопіюй)»**: ключ замаскований,
   **«👁 Показати»** / **«📋 Копіювати»**. Там же готова команда перевірки й посилання на консоль API.

> 💡 Ключ для RAG-ПК (база знань) створюється не тут, а кнопкою **«🔑 Створити ключ для RAG»** на сторінці
> [База знань](guide:ai/knowledge-base). Ключ сайту магазину зручно отримати кодом **«🔗 Підключити сайт»** —
> див. [Адмінка сайту й підключення](guide:shop/site-admin).

## Права (scopes)

| Право в Minerva | Код | Що дозволяє |
|---|---|---|
| Склад — залишки, рухи, локації (читання) | `stock:read` | залишки, журнал рухів, локації, перевірка кошика |
| Склад — прихід, списання, інвентаризація | `stock:write` | рухи складу, інвентаризація |
| Товари — читання / запис | `products:read` / `products:write` | каталог, категорії, товари магазину |
| Замовлення — читання / запис | `orders:read` / `orders:write` | замовлення: читати, створювати, змінювати статус, скасовувати |
| Доставка — відправлення і трекінг (читання) | `shipments:read` | відправлення, трек-номери, статус доставки |
| Клієнти — читання / запис | `customers:read` / `customers:write` | клієнти CRM |
| Закупівлі — читання / запис | `purchases:read` / `purchases:write` | закупівлі зовнішньої CRM ([Закупівлі з CRM](guide:api/purchases)) |
| Акаунти покупців магазину — читання / запис | `accounts:read` / `accounts:write` | кабінет покупця на сайті ([Кабінет покупця](guide:shop/customer-accounts)) |
| Вебхуки — перегляд / створення, зміна, видалення | `webhooks:read` / `webhooks:write` | вебхуки цього ключа ([Вебхуки](guide:api/webhooks)) |
| База знань — стрічка / статуси | `knowledge:read` / `knowledge:write` | лише службовий ключ RAG-ПК, не магазин |

Типові набори:

| Для чого | Права |
|---|---|
| Сайт магазину | `stock:read`, `orders:read`, `orders:write`, `shipments:read`, `webhooks:read`, `webhooks:write` (+ `products:read`, `accounts:*` для магазину Minerva) |
| Зовнішня CRM, закупівлі | `purchases:read`, `purchases:write` (+ `webhooks:*` для вебхука, `stock:read` для залишків) |
| RAG читає каталог | лише `products:read` і `stock:read` |
| Партнер бачить лише наявність | `stock:read` + обмеження (приклад нижче) |

### Ключ сайту магазину

Ключ, прив'язаний до магазину (поле **«Магазин»** або **«Джерело замовлень»** = код магазину; так створює
«🔗 Підключити сайт»), — це ключ сайту, і з будь-якими правами він бачить лише свій магазин:

- **замовлення** — лише цього магазину (`GET /orders/`, картка, скасування); чуже замовлення — 404;
- **зміна замовлення** (`PATCH /orders/{id}/`) — лише поля оплати `payment_status`, `payment_reference`,
  `payment_method`; решту (суму, позиції, склад) Minerva відкидає й називає у `ignored_fields`;
- **товари** (`/products/`) — лише видимі в магазині, без закупівельної ціни й внутрішніх приміток
  (каталог для сайту — `/shop/products/`);
- **вебхуки** — події лише цього магазину: `stock.changed` — про його товари, замовлення й доставка — лише його.

## 🔍 Що бачить і що може змінити ключ

Блок у картці ключа: скільки адрес API ключ читає, скільки змінює (і які саме), скільки заборонено правами.
Кнопка **«🔍 Таблиця можливостей, приклад даних і симуляція»** — кожна адреса з полями, які ключ отримує й може
змінити, **«👁 Приклад даних»** (що ключ отримав би зараз) і **«🧪 Що змінить запит»** (перевірка тіла запиту без
запису). Докладно — [Що бачить і що може змінити ключ](guide:api/key-insight).

## 🛡 Обмеження

Кожне поле порожнє — без обмеження. Діють разом із правами.

| Поле | Що робить | Коли не можна |
|---|---|---|
| **«Дозволені IP-адреси»** | лише з цих адрес чи мереж: `203.0.113.5`, `10.0.0.0/24` (через кому чи з нового рядка). Адреса — справжня: заголовок `X-Real-IP` діє лише від проксі NAS, підставити його ззовні не можна | 401, у відповіді — адреса, з якої прийшов запит |
| **«Запитів за хвилину»** | свій ліміт замість загального (120) | 429 + `Retry-After` |
| **«Запитів за годину»** / **«Запитів за добу»** | календарна година / доба (час Berlin); відмови в ліміт не рахуються | 429 з причиною |
| **«Різних записів за добу»** | скільки різних товарів / замовлень ключ побачить за добу; уже переглянуті сьогодні — без обмежень, у списках решта прихована | один запис понад ліміт — 429 `daily_items_limit` |
| **«Лише ці поля у відповідях»** | напр. `sku, available` — у записах лишаються тільки ці поля | — |

**«Використано зараз»** — скільки ключ уже використав за цю годину, сьогодні й різних записів сьогодні.

Приклад «партнер бачить лише кількість на складі, не більше 10 товарів на добу, лише зі свого сервера»:
право «Склад — залишки…(читання)», **«Лише ці поля у відповідях»** = `sku, available`, **«Різних записів за добу»**
= `10`, **«Запитів за добу»** = `200`, **«Дозволені IP-адреси»** = адреса сервера партнера.

## 📜 Журнал запитів

**«Журнал запитів»** у картці ключа — що записувати: **«Усі запити»**, **«Лише зміни (POST / PATCH / DELETE) і
помилки»** (для ключа, який постійно опитує, як RAG), **«Лише помилки й відмови»**, **«Не записувати»**.

**«Активність»** у картці ключа: запити сьогодні й за 7 днів, помилки, IP-адреси з часом останнього звернення,
що найчастіше робив, останні 10 запитів.

[📜 Журнал API](/admin/api/apirequestlog/) — усі запити всіх ключів (і спроби з невідомим ключем): час, ключ,
**«Що сталося»** — одним реченням («API RAG прочитав список товарів зі складом — 169 записів (сторінка 1,
page_size 500)»), IP, запит (секретні параметри приховано), **«Код»**, **«Що»** — скільки записів і які
артикули / номери, примітка («приховано 3: ліміт 10 різних записів за добу», «адреса не в Дозволених IP»),
тривалість. У картці запиту — **усі** записи відповіді з посиланнями й **«Що змінилось»** (назви полів тіла без
значень і що відповіла Minerva). Тіло запиту не записується.

**«📊 Аналіз журналу»** (кнопка вгорі журналу і в картці ключа) — графік по днях, відмови, які товари й замовлення
отримала програма, IP, програми, кожна зміна, CSV — [Аналіз журналу API](guide:api/log-analysis).

Фільтри справа: **«Ключ»**, **«Відповідь»** (✅ Успішні, ⚠ Помилки, 🔒 Ключ не прийнято (401), ⛔ Немає права
(403), ⏳ Ліміт (429), ❌ Помилка сервера (5xx)), **«Що робив»** (👁 Читання / ✏️ Зміни), метод; дата зверху;
пошук за IP, адресою, артикулом. Записи зберігаються 60 днів.

У списку ключів колонки **«Сьогодні»** (запитів і помилок, остання IP — клік відкриває журнал ключа) і
**«Обмеження»** (🛡 IP, /хв, /год, /добу, поля).

## Як замінити ключ

1. Створіть новий ключ з тими самими правами.
2. Вставте його в програму (сайт, CRM) і перевірте — у журналі з'являються запити нового ключа.
3. У старому ключі зніміть **«Активний»**. Видаляти не обов'язково — журнал старого ключа лишиться.

## Часті питання та проблеми

**401** — ключ не прийнято: опечатка, ключ вимкнений чи прострочений, або запит не з **«Дозволених IP-адрес»**
(у відповіді видно, з якої адреси прийшов запит). У журналі такі запити — «невідомий …» або з приміткою.

**403** — у ключа немає права; назва права — у відповіді (`detail`). Додайте галочку в **«Права доступу»**.

**429** — вичерпано ліміт за хвилину / годину / добу (у `detail` — який) або **«Різних записів за добу»**
(`daily_items_limit`). Програма має почекати `Retry-After` секунд.

**Запити з консолі API Minerva відхиляються з 401** — консоль перевіряє **«Дозволені IP-адреси»** ключа за IP
вашого комп'ютера: додайте його або візьміть ключ без обмеження ([Консоль API](guide:api/console)).

**Ключ потрапив у чужі руки** — одразу зніміть **«Активний»**, створіть новий і перегляньте журнал старого.
