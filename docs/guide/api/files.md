## Що це

Через [MCP](guide:api/mcp) і REST API агент працює з **файлами** Minerva від імені людини ключа (з її правами):

- **знаходить** файли замовлення (рахунки, інвойси, пакувальні листи), даташит і фото товару, документи проєкту й
  клієнта, файли запиту постачальникам і відповіді постачальників, версії Angebot, вкладення листа (лише ваших
  скриньок);
- **завантажує** їх і читає текст (PDF по сторінках, DOCX, XLSX, TXT, CSV);
- **передає** свій файл у Minerva — з диска, з тексту або з адреси в інтернеті;
- **вкладає** будь-який із цих файлів у лист (`propose_email`) і **кладе** файл до замовлення, проєкту чи клієнта.

Лист і файл до замовлення — лише **пропозиції**: застосовуєте ви ✓ у [🧩 Завданнях агенту](/admin/agent/agenttask/),
як і решту пропозицій агента.

Кожен файл має **ref** — коротке посилання, напр. `order:12:Rechnung_102497269.pdf`, `invoice:5`, `offer:9`,
`msg:345:0` (вкладення листа), `datasheet:AN220213-01C`, `upload:7` (файл, який передав агент).

> 🔒 Вкладення листів і пошук в історії пошти — лише через [особистий ключ](guide:api/keys) («🔒 Лише я»), де агент —
> ви самі.

## Як працювати (MCP)

1. **Знайти файл**: `list_files` з одним параметром — `order` (номер замовлення), `product` (артикул), `project`
   (P-…), `request` (RFQ-…), `customer`, `offer` (A-…), `mail` (id листа) або `uploads: true`. У відповіді — назви,
   розміри й ref.
2. **Подивитися**: `get_file` дає посилання на завантаження без ключа (діє годину; Claude Code завантажить його
   `curl`), картинку агент бачить одразу; `read_file` — текст документа.
3. **Передати свій файл**: `upload_link` дає посилання на 30 хвилин — Claude Code сам виконає
   `curl -F "file=@./Angebot.pdf" "<посилання>"`; або `upload_file` (base64 до 10 МБ, текст, `url` — публічна
   адреса). Файл лежить у Minerva 30 днів і видно його лише вам.
4. **Вкласти в лист**: `propose_email` з `attachments: ["upload:7", "invoice:5", "order:12:…"]` — до 10 файлів,
   25 МБ разом. На сторінці перевірки над листом — «📎 Вкладення» з посиланнями на кожен файл; після ✓ — чернетка з
   усіма вкладеннями. Angebot і рахунок після відправки стають «надісланими».
5. **Покласти до замовлення / проєкту / клієнта**: `propose_save_file` (`ref` + `order`, `project` або `customer`)
   → ✓ — файл у документах замовлення, документ бази знань проєкту або документ клієнта. Той самий файл удруге не
   дублюється.

Програми й скрипти (.exe, .bat, .js, .ps1…) Minerva не приймає й у лист не вкладає.

## REST API

Ключ — той самий, що для MCP (`Authorization: Token <ключ>`, `agent:read` / `agent:write`).

| Адреса | Що робить |
|---|---|
| `GET /api/v1/files/?order=102497269` | файли об'єкта (або `product`, `project`, `request`, `customer`, `offer`, `mail`, `uploads=1`) |
| `GET /api/v1/files/download/?ref=…` | сам файл |
| `GET /api/v1/files/text/?ref=…` | текст файлу (`first_page`, `last_page` для PDF) |
| `POST /api/v1/files/` | передати файл: multipart `file` (кілька) або JSON `{name, content_base64}` (замість `content_base64` — `text` чи `url`) → `ref` |
| `GET /api/v1/rag/datasheets/?q=antenna 5.8 GHz SMA` | 🔎 RAG-ПК: пошук по всіх даташитах і каталогу |
| `GET /api/v1/rag/history/?q=…&customer=&project=` | 🔎 RAG-ПК: пошук в історії пошти й документах (🔒 особистий ключ) |

Приклад: передати файл і отримати ref:

```
curl -H "Authorization: Token <ключ>" -F "file=@./Angebot.pdf" {{base_url}}/api/v1/files/
```

## Часті питання та проблеми

**«вкладення пошти — лише через 🔒 особистий ключ».** Ключ спільний — створіть [особистий](guide:api/keys).

**403 на `upload_file` чи `POST /api/v1/files/`.** У ключа лише `agent:read` — додайте `agent:write`.

**«посилання застаріло».** Посилання з `get_file` діє годину, з `upload_link` — 30 хвилин: попросіть агента ще раз.

**«такого файлу немає (або його вже прибрано…)».** Файли, передані агентом, лежать 30 днів; пропозиція з файлом
подовжує строк.

**`search_history` немає в списку інструментів.** Потрібен 🔒 особистий ключ, налаштована база знань і право
«🔎 Пошук у базі знань» — див. [🔐 Доступ до бази знань і RAG](guide:ai/knowledge-access).
