## Що це

**REST API** — вхід у Minerva для інших програм: сайт магазину бере залишки й передає замовлення, зовнішня
CRM передає закупівлі, RAG читає каталог, ваші скрипти роблять інвентаризацію. Кожна програма отримує свій
**ключ API** з потрібними правами; усе, що вона робить, видно в журналі.

Адреса API цього сервера:

```text
{{base_url}}/api/v1/
```

## Як підключитись — перший запит за 5 хвилин

1. Відкрийте [🔑 API Токени](/admin/api/apikey/) → **«Додати API Ключ»**.
2. **«Назва»** — хто користуватиметься, напр. `webshop`; у **«Права доступу (scopes)»** позначте потрібне
   (для першої перевірки досить **«Склад — залишки, рухи, локації (читання)»**). **«Зберегти»**.
3. Розгорніть **«Технічна інформація»** → **«API Ключ (скопіюй)»** → **«📋 Копіювати»**.
4. Перевірте підключення (замість `$MINERVA_KEY` — скопійований ключ):

```bash
curl -H "Authorization: Token $MINERVA_KEY" {{base_url}}/api/v1/ping/
```

Відповідь — назва ключа і його права:

```json
{"ok": true, "server_time": "2026-10-29T09:00:00Z", "key": "webshop",
 "scopes": ["stock:read"], "default_source": "webshop", "user": null}
```

Те саме без командного рядка — [консоль API](guide:api/console) у Minerva.

> ⚠️ Ключ — лише в серверному коді програми (PHP, Python, Node.js), у змінній оточення. Ніколи не вставляйте
> його в JavaScript сторінки: його побачить кожен відвідувач. У Windows PowerShell пишіть `curl.exe`, а не `curl`.

## Основні правила

- **Авторизація** — заголовок `Authorization: Token <ключ>` у кожному запиті.
- **Формат** — JSON (`Content-Type: application/json` для POST / PATCH).
- **Списки посторінково**: `?page=2&page_size=200` (до 500). Відповідь: `{count, next, previous, results}`.
- **Сортування**: `?ordering=-available`, `?ordering=sku`.
- **Повтори безпечні.** Замовлення з тим самим номером, рух складу з тим самим `external_key`, закупівля з тим
  самим `external_id`, доставка з тим самим `delivery_id` — не дублюються. Тож при збої мережі програма просто
  повторює той самий запит.
- **Видалення** товарів, замовлень і клієнтів через API немає (відповідь 405) — замовлення скасовується
  `POST /orders/{id}/cancel/`.
- **Ліміт** — 120 запитів за хвилину на ключ (або свій у ключа); понад нього — 429 і заголовок `Retry-After`.
- **Помилки** — у тілі `detail` (текст для людини) і часто `code` (для програми).
- **Виклик із браузера** (CORS) дозволено лише з ключем у заголовку, без cookie.

## Коди відповідей

| Код | Що означає | Що робити |
|---|---|---|
| 200 / 201 | гаразд / створено | — |
| 400 | помилка в даних (`invalid_lines` — невідомий артикул тощо) | виправити запит |
| 401 | немає ключа, ключ невірний, вимкнений, прострочений або запит не з дозволеної IP-адреси | перевірити ключ і [обмеження](guide:api/keys) |
| 403 | у ключа немає права — назва права в `detail` | додати право ключу |
| 404 | запис не знайдено (`sku_not_found`) | перевірити артикул / номер |
| 409 | конфлікт: `insufficient_stock`, `already_shipped`, `over_receipt` | див. сторінку сценарію |
| 429 | ліміт запитів або `daily_items_limit` | зачекати `Retry-After` секунд |
| 5xx | помилка сервера Minerva | повторити пізніше — дублів не буде |

Повторювати варто лише 429, 5xx і збої мережі.

## Безпека — коротко

- Окремий ключ для кожної системи (магазин, CRM, тест, скрипти) — тоді будь-який можна вимкнути, не зачепивши інших.
- Лише потрібні права; магазину зазвичай не потрібні зміна складу, товарів і клієнтів.
- Для тимчасових ключів — **«Дійсний до»**; для партнерів — **«🛡 Обмеження»** (IP, ліміти, поля).
- Перший тиждень після запуску дивіться [📜 Журнал API](/admin/api/apirequestlog/) — хто, звідки й що робить.
- Вебхуки — лише на HTTPS-адресу, з перевіркою підпису ([Вебхуки](guide:api/webhooks)).
