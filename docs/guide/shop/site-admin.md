## Що це

Сайт магазину спілкується з Minerva двома каналами:

- **ключ API** — сайт бере каталог, ціни, зони доставки, створює замовлення й працює з кабінетом покупця;
- **вебхук** — Minerva одразу повідомляє сайт про зміни складу й цін (подія `stock.changed`), щоб він не чекав
  свого кешу.

На самому сайті є сторінка **`/admin/`** (напр. `https://shop.example.com/admin/`) — ключі, паролі, оплата,
пошта, налаштування магазину без перенесення файлів. Вхід туди — **логіном і паролем Minerva** тих людей, яким ви
дали доступ. Пароль у сайт не потрапляє: сайт питає Minerva своїм ключем.

## Хто має доступ до адмінки сайту

Внизу картки магазину — таблиця **«👥 Доступ до адмінки сайту»**:

1. **«Додати ще один …»** → **«Користувач Minerva»** (пошук за іменем).
2. **«Роль на сайті»**:
   - **Адміністратор сайту** — усі налаштування, ключі й паролі, підключення;
   - **Менеджер магазину** — налаштування без ключів і паролів;
   - **Перегляд** — лише бачить налаштування.
3. **«Доступ дозволено»** — зніміть, щоб тимчасово закрити вхід. **«Останній вхід на сайт»** заповнюється сам.
4. **«Зберегти»**.

На сайті користувач входить своїм логіном або email Minerva. Після 5 невдалих спроб вхід для цього логіна
блокується на 15 хвилин. Якщо Minerva недоступна, сайт пускає за останнім успішним входом (до 30 днів).

> ⚠️ Дорожня карта вимагає хоча б одного **«Адміністратор сайту»** — без нього ніхто не зможе змінити ключі чи
> перепідключити сайт.

## Як підключити сайт кодом (рекомендовано)

1. Картка магазину → блок **«🌐 Адмінка сайту»** → **«🔗 Підключити сайт (код)»**.
2. Угорі з'явиться код із 10 знаків (напр. `K7QMX-4HNPA`, без O / I і 0 / 1), адреса Minerva й час, до якого він
   діє, — **30 хвилин**. Код одноразовий; новий код скасовує попередній невикористаний.
3. На сайті відкрийте `/admin/` → **«🔌 Minerva»** → **«🔗 Підключити до Minerva кодом»**, вкажіть адресу Minerva
   і код.
4. Сайт отримає **власний ключ API** («Сайт shop.example.com», з правами каталогу й замовлень, а якщо кабінет
   покупців увімкнено — і кабінету) і **вебхук** на `https://shop.example.com/api/shop/webhook.php`.
   Попередній ключ, виданий цьому сайту кодом, вимикається; ключі, створені вручну, не змінюються.
5. Натисніть **«🔌 Перевірити зв'язок із сайтом»** (нижче).

Блок **«🌐 Адмінка сайту»** також показує **«Доступ мають:»** і журнал останніх подій адмінки сайту:
**«Коли»**, **«Сайт»**, **«Хто»**, **«Дія»** (вхід, невдалий вхід, змінено налаштування, підключено кодом, вихід,
перевірка), **«Поля»** — лише назви змінених полів, без значень.

## Ключ і вебхук вручну

Якщо сайт не вміє підключатися кодом:

1. [🔑 API Токени](/admin/api/apikey/) → новий ключ: поле **«Магазин»** = ваш магазин, права `products:read`,
   `orders:read`, `orders:write` (з кабінетом — ще `accounts:read`, `accounts:write`) — [Ключі API](guide:api/keys).
2. На сайті ключ вставляється в `/admin/` → «🔌 Minerva» (на старих сайтах — `private/shop-config.php`,
   `'minerva_token'`).
3. [📡 Вебхуки](/admin/api/webhook/) → URL `https://shop.example.com/api/shop/webhook.php`, подія `stock.changed`;
   секрет — той самий, що на сайті в `/admin/` → «🔌 Minerva» — [Вебхуки](guide:api/webhooks).

Блок **«Підключення»** картки, рядок **«Ключі API»** — які ключі працюють з магазином (замасковано): «прив'язаний»
(поле «Магазин»), «за джерелом «код»», або «Без прив'язки… працюють з магазином за замовчуванням».

> ℹ️ Ключ сайту видає лише Minerva. Який магазин бачить ключ: поле «Магазин» ключа → магазин, код якого
> збігається з «Джерелом замовлень» ключа → магазин **«За замовчуванням»**.

## «🔌 Перевірити зв'язок із сайтом»

Блок **«Підключення»** → **«🔌 Перевірити зв'язок із сайтом»**. Адреса береться з поля **«Адреса сайту»** —
можна перевірити й ще не збережену (напр. тестовий домен). Перевірка триває до хвилини, бо сайт сам звертається
до Minerva. Результат — список рядків ✅ / ⚠️ / ❌ / ℹ️:

| Рядок | Що перевіряється |
|---|---|
| **Ключ «…»** | активний, не прострочений, усі потрібні права, коли востаннє використаний |
| **Minerva → сайт** | сайт відповідає за адресою, магазин на ньому увімкнено |
| **Сайт → Minerva** | сайт отримав свіжий каталог, а не показує стару копію |
| **Товари / Доставка / Кабінет покупця / Оплата на сайті** | сайт бачить те саме, що налаштовано в Minerva |
| **В обидва боки** | під час перевірки сайт сам звернувся до Minerva своїм ключем |
| **Вебхук «…»** | сайт прийняв підписаний тестовий ping — секрет збігається |
| **Помічник на сайті**, **Фото й даташити** | що сайт звітує про чат і копії файлів |

## Часті питання та проблеми

**«Код недійсний, уже використаний або протермінований»** — створіть новий кодом **«🔗 Підключити сайт (код)»**.

**❌ «… немає (HTTP 404). Домен має вказувати на папку public (dist) сайту»** — домен сайту налаштований не на
ту папку або адреса неправильна.

**❌ «Сайт відповідає, але магазин на ньому не запускається (HTTP 503)»** — на сайті немає або неповний файл
налаштувань (адреса Minerva, ключ), PHP не може писати в `private/runtime`, або сайт ще ні разу не отримав каталог.

**❌ «Сайт не зміг оновити каталог з Minerva і показує стару копію»** — на сайті неправильна адреса Minerva чи
ключ, або хостинг блокує вихідні HTTPS-з'єднання.

**Вебхук: HTTP 401** — секрет у Minerva не збігається з секретом на сайті. **HTTP 404** — неправильна адреса;
правильна закінчується на `/api/shop/webhook.php`. Найпростіше — підключити сайт кодом ще раз.

**Сайт переадресовує на іншу адресу** — впишіть у **«Адреса сайту»** кінцеву адресу (з `https://` і `www`, якщо
сайт їх вимагає).
