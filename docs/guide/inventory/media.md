## Що це

У кожного товару може бути **фото** й **даташит** (PDF). Вони показуються:

- мініатюрою й значком 📄 у колонці **🖼** [списку товарів](/admin/inventory/product/), в
  [огляді складу](/admin/inventory/reorderproxy/supply/) і в «Асортимент і ціни» магазину; бліді значки —
  немає фото чи даташита;
- в інтернет-магазинах — сайт бере їх з Minerva ([Фото й даташити для сайту](guide:shop/media));
- даташит потрапляє в базу знань як документ товару, якщо це увімкнено ([Документи бази знань](guide:ai/knowledge-documents)).

Клік на мініатюру — фото, на 📄 — даташит у новій вкладці. В огляді складу досить навести мишку на
артикул — з'явиться перегляд даташита (перемикач **«🌐 URL»** / **«📁 Файл»**, **«↗ Відкрити»**).

## Посилання чи файл

У картці товару розділ **«🔗 Медіа та документи»** (розгорніть):

| Поле | Що вписати |
|---|---|
| **«Посилання на Datasheet»** | адреса PDF на сайті виробника чи на вашому сервері |
| **«Datasheet (PDF файл)»** | PDF з комп'ютера — **має пріоритет** над посиланням |
| **«Зображення (URL)»** | адреса фото |
| **«Зображення (файл)»** | фото з комп'ютера — має пріоритет над посиланням |
| **«Даташит: спільний файл»**, **«Фото: спільний файл»** | для посилань за правилом (див. нижче) |

Поруч — перегляд фото й посилання на даташит, а також блок **«🖼 Для сайту»** — чи забрав сайт магазину
файли з Minerva.

Мініатюри (96 px) Minerva робить сама й запам'ятовує; заміна фото — нова мініатюра. Якщо фото за посиланням
недоступне, у списку буде **🖼✕**.

## Знайти товари без фото чи даташита

- список товарів → фільтр **«Фото / даташит»**: **«🖼 Без фото»**, **«📄 Без даташита»**, **«Без фото й без
  даташита»**, **«З фото»**, **«З даташитом»**, **«❌ Посилання не відповідає (перевірка для сайту)»**;
  наприклад, [усі без фото](/admin/inventory/product/?media=no_image);
- [огляд складу](/admin/inventory/reorderproxy/supply/) → кнопки **«🖼 Без фото»** і **«📄 Без даташита»**
  (з кількістю).

## Посилання за правилом

Якщо фото й даташити лежать на вашому сервері з назвою файлу = артикулу (`FT220407.pdf`, `FT220407.jpg`),
не треба вписувати посилання кожному товару — задайте **правило**.

### Як налаштувати

1. [⚙️ Налаштування складу](/admin/inventory/inventorysettings/) → блок **«🖼️ Кешування медіа (Datasheet / Фото)»**.
2. **«Правило: посилання на даташит»** — досить початку адреси, напр.
   `https://docs.example.com/datasheets/download.php?file=`. Minerva сама допише `{key}.pdf`.
3. **«Правило: посилання на фото»** — так само, Minerva допише `{key}.jpg`.
4. **«Зберегти»**. Під полями — **«Посилання за правилом»**: приклад для першого товару.

`{key}` — артикул товару (або «спільний файл», якщо задано). Артикул посередині адреси — впишіть `{key}` самі:
`https://docs.example.com/files/{key}/datasheet.pdf`.

> ℹ️ Фото бувають `.jpg` і `.png`: якщо файлу з розширенням правила немає, Minerva під час перевірки
> пробує `.png`, `.jpeg`, `.webp` і бере те, що є.

### Сформувати й перевірити

1. **«🔗 Сформувати й перевірити посилання →»** у налаштуваннях (або в списку товарів позначте товари → дія
   **«🔗 Посилання на фото й даташити за правилом…»**).
2. На сторінці [Посилання на фото й даташити за правилом](/admin/inventory/inventorysettings/media-links/):
   **«Для яких товарів»** — **«усі активні»**, **«лише в магазинах»** або **«вибрані в списку товарів»**;
   **«Що»** — 📄 Даташит / 🖼 Фото; **«перевірити, чи посилання відповідають»** — Minerva відкриє кожне
   посилання й перевірить, що там справді фото чи PDF, а не сторінка помилки.
3. **«🔍 Сформувати й перевірити»** — нічого не записується, хід видно на сторінці.
4. У звіті для кожного товару — **«Зараз»**, **«Буде»** і **«Що зробити»** (таблиця нижче); кнопки над
   звітом показують лише рядки однієї дії.
5. Перевірте позначки → **«✍️ Записати вибрані»**. Магазини потім самі перевірять змінені файли.

| Що зробити | Що означає | Позначено одразу |
|---|---|---|
| **заповнити** | посилання ще немає, нове відповідає | так |
| **замінити** | є інше посилання, нове відповідає | так |
| **залишити поточне — нове не відповідає** | старе працює, нове — ні | ні |
| **нове не відповідає** | файлу за правилом немає | ні |
| **без змін** | посилання вже таке | ні |

Змінили правило після перевірки — сторінка попросить запустити перевірку ще раз.

### Спільні файли

Коли кілька товарів мають одне фото чи даташит (кабель різної довжини — один даташит):

- у списку товарів позначте товари (наприклад, фільтром **«Категорія»**) → дія **«🔗 Спільне фото / даташит
  (посилання або файл) для вибраних…»**;
- або **готове посилання** — **«🖼 Готове посилання на фото»** / **«📄 Готове посилання на даташит»**
  (однакове для всіх вибраних);
- або **спільний файл за правилом** — галочки 🖼 Фото / 📄 Даташит і **«Файл якого товару»** (один з вибраних)
  чи **«…або назва файлу»**, напр. `AN050201-01C-175-MHF1` (з розширенням `X.png` — береться як є).

Minerva одразу перевіряє посилання й пише «✅ відповідає» або «⚠ …». Спільні файли видно внизу сторінки
перевірки — **«🔗 Спільні файли»**.

## Копії файлів на сервері

**«📥 Завантажити відсутні файли на сервер»** у [налаштуваннях складу](/admin/inventory/inventorysettings/)
(**«Статус медіафайлів»**): для товарів, де є посилання, але немає файлу, Minerva завантажує PDF і фото до себе.
Такі файли відкриваються швидше й доступні, навіть коли сайт виробника не працює. Тип файлу Minerva
визначає за вмістом, тож посилання на кшталт `download.php?file=…` теж зберігаються правильно.

## Часті питання та проблеми

**🖼✕ замість мініатюри** — посилання на фото не відкривається або там не картинка. Перевірте посилання в
картці або запустіть перевірку за правилом.

**«нове не відповідає» для всіх товарів** — у правилі помилка або сервер з файлами недоступний з Minerva.
Відкрийте приклад з налаштувань у браузері.

**Даташит у картці є, а сайт показує старий** — сайт забирає файли за своїм розкладом; стан — у блоці
**«🖼 Для сайту»** і на сторінці [🖼 Фото й даташити](/admin/shop/productmedia/) магазину.
