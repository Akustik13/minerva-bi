# 📚 Гід по Minerva — як писати сторінки

Гід — довідник **для людей, які працюють у Minerva** (менеджери, адміністратор), а не для розробників.
Він відкривається в Minerva на `/guide/` і з нього ж відповідає помічник «Minerva». Технічні подробиці
(файли, функції, міграції) лишаються в `CLAUDE.md`; гід пояснює, **що це, де це, як налаштувати й як
користуватись**.

## Правило

Кожна нова функція чи зміна поведінки → оновлена сторінка гіда **в тому самому коміті** (як `CLAUDE.md`).
Перевірка: `python manage.py guide_check --settings=tabele.settings_test` (тест `guide/tests.py` робить те саме).

## Де лежить

```
docs/guide/<розділ>/_section.md     ← назва розділу, значок, порядок, вступ
docs/guide/<розділ>/<сторінка>.md   ← сторінка; адреса в Minerva: /guide/<розділ>/<сторінка>/
```

Назва файлу — латиницею з дефісами: `knowledge-sources.md`. Одна сторінка — одна тема (функція або
налаштування), 150–600 рядків — забагато, краще розділити.

## Шапка сторінки (обов'язково)

```
---
title: Джерела знань
order: 30
summary: Папки й сайти, які Minerva сама передає в базу знань — файли з ПК, папки NAS, посилання.
where: Minerva AI → 📂 Джерела знань
urls: /admin/rag_assistant/knowledgesource/, /admin/rag_assistant/knowledgesource/add/
roles: адміністратор, менеджер
keywords: папка, файли, завантажити, сайт, sitemap, даташит, RAG, база знань
related: ai/knowledge-base, ai/knowledge-overview
---
```

- `title` — як пункт меню або кнопка в Minerva;
- `summary` — одне речення: що це й навіщо;
- `where` — шлях у меню так, як його бачить людина (з емодзі, як у меню);
- `urls` — адреси сторінок Minerva без домену, через кому (лише списки й сторінки, без номерів записів);
  у шапці сторінки стають кнопками «Відкрити →»;
- `keywords` — слова, якими люди шукатимуть (різними мовами теж: «Angebot, пропозиція, offer, КП»);
- `related` — slug-и пов'язаних сторінок гіда (`розділ/сторінка`).

## Як писати

- Українською, на «ви», коротко. Спершу — що це і коли потрібно, потім — як.
- **Назви кнопок, полів і пунктів меню — точно як у Minerva**, жирним і в лапках: **«📤 Завантажити файли…»**.
  Брати їх із шаблонів і `admin.py`, не вигадувати.
- Кроки — нумерованим списком, кожен крок — одна дія: де натиснути → що з'явиться.
- Кожне згадане місце Minerva — посиланням: `[📂 Джерела знань](/admin/rag_assistant/knowledgesource/)`.
- Посилання на іншу сторінку гіда — `[Огляд бази знань](guide:ai/knowledge-overview)`.
- Зовнішні посилання — повністю `https://…` (відкриваються в новій вкладці).
- Приклади — реальні за формою, вигадані за змістом: артикул `FT220407`, замовлення `102497269`,
  клієнт «Muster GmbH», email `kunde@example.com`. Без справжніх клієнтів, паролів, ключів, адрес листів.
- Підказки й попередження — цитатою: `> 💡 Порада …`, `> ⚠️ Увага …`, `> ℹ️ …`.
- Таблиці — для порівнянь («що робить кожен режим»).
- Код і приклади запитів — блоком ``` з мовою (`bash`, `python`, `json`). `{{base_url}}` у тексті й коді
  замінюється адресою сервера, на якому відкрито гід.

## Типова структура сторінки

```
## Що це
## Де знайти            (якщо шляхів кілька; основний — у шапці)
## Як налаштувати       (кроки)
## Як користуватись     (щоденні дії, кроки)
## Приклади
## Часті питання та проблеми
```

Не всі розділи потрібні кожній сторінці.

## API

Рядок `{{api_endpoints}}` вставляє **з коду** всі адреси REST API з правами ключа й прикладами curl і
Python (`guide/api_docs.py`); `{{api_endpoints:orders}}` — лише адреси, що починаються з `orders`.
Нові дії API з'являються в гіді самі; текст пояснює сценарії («як сайт створює замовлення»).

## Що перевіряє guide_check

- шапка: `title`, `summary`, `where`; розділ має `_section.md`;
- кожне посилання `/…` і кожна адреса в `urls` — справжня адреса Minerva;
- кожне `guide:…` і `related` — існуюча сторінка;
- `{{api_endpoints:…}}` — є такі адреси API.
